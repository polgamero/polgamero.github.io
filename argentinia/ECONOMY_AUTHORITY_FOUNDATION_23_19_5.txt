TRUST MODEL
- UID is derived only from authenticated request.auth.uid.
- Client-supplied authority fields (uid, points, fichas, collection, decks, inventory, enhancements, starterCardIds, cardIds) are rejected in bootstrap/starter calls.
- Initial account balances and empty economic state are created server-side.
- Initial starter contents are generated server-side from an exact trusted snapshot of the 880-card pool + Deck Intelligence.
- Client may choose only the allowed starter color identity (1 or 2 colors).

IDEMPOTENCY
Every mutation uses a stable operationId and economyOperations/{uid}_{operationId} receipt.
- same operationId + same normalized payload => exact committed result is returned (replay)
- same operationId + different payload/type => OPERATION_ID_PAYLOAD_MISMATCH
- operation receipt records engine/economy protocol/schema + trusted result.
- committed receipt recovery remains available even if the economy kill switch is later disabled.

ROLLOUT
Client understands three states:
- shadow: legacy production behavior; Functions are not required.
- server_preferred: Functions first, temporary legacy fallback.
- server_required: Functions required; failure is fail-closed.
Default when gameConfig/economy does not exist is shadow.
